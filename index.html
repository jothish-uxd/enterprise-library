An experiment in accessible enterprise patterns by Jothish, © 2026

Enterprise software, accessible by default.

Foundations, components and whole patterns for dense, task-heavy screens: data tables, filters, bulk actions and multi-step forms, plus admin screens like audit logs and usage caps. Each one decides where focus goes, what a screen reader hears, and how every state looks.

$npm install github:jothish-uxd/enterprise-library#v0.3.14

How it’s built

Three layers, each built on the one before. Every layer is accessible on its own, and each one up takes care of more of the screen: tokens make every value consistent, components get one control right, and patterns get the whole task right.

  1. Layer 1 · FoundationsTokensColour, type, spacing, radius, shadow, control heights and the focus ring. Every value in the library comes from here.
  2. Layer 2 · ComponentsComponentsButton, Input, Select, Checkbox, Table, Tooltip and more. Each one names itself, follows its WAI-ARIA pattern, and says why when it’s unavailable.
  3. Layer 3 · PatternsPatternsData table, Bulk actions, Multi-step form, Command palette: components working together on a real screen.
  4. Layer 4 · laterTemplatesReview queue, Settings page, Admin console: whole screens, built from the patterns.

Overview

Use cases

Enterprise Library is for dense, task-heavy software: the screens people spend their working day in, where getting focus, wording and state right matters more than brand colour.

  • Admin consoles

    Audit logs, roles, usage caps, configuration and reports, built from the admin patterns.

  • Review queues

    Compliance review, approvals and triage: filter, choose many, act once, undo.

  • Hiring and assessment tools

    Candidate tables, pipelines that filter (stat filter), choice cards for setup steps.

  • Data and ML workbenches

    Model cards with stats, run tables, selectable configurations.

  • Product demos and case studies

    Present a working app inside a page with a browser frame; the page tells the story.

  • Long tasks and setup flows

    Multi-step forms with saved drafts and one error summary per step.

Which layer to reach for

When it isn’t the right fit

  • Marketing and brand sites. The library is monochrome on purpose; colour only ever means an error, warning or success message.
  • Consumer apps that need playful motion or illustration. Motion here is minimal and switches off with reduced motion.
  • Data visualisation. Charts arrive in 0.4.0; until then, use Accessible Charts.

Patterns, as they’ll ship

The patterns are being built as React components next. This is the intended API: describe your rows and columns, then name the filters and actions. Focus handling, announcements and empty states come with the pattern.

AccessRequests.jsx
import { DataTable, FilterBar, BulkActions, DetailsSheet } from "enterprise-library";
import "enterprise-library/styles.css";

export function AccessRequests({ rows, onUpdate }) {
  return (
    <DataTable
      caption="Access requests"
      rows={rows}
      rowKey="id"
      itemName={{ one: "request", other: "requests" }}
      columns={[
        { key: "requester", header: "Requester", rowHeader: true, sortable: true },
        { key: "system", header: "System", priority: "low" },
        { key: "status", header: "Status", sortable: true },
        { key: "submitted", header: "Submitted", sortable: true },
      ]}
      filters={<FilterBar search={["requester", "system"]} facets={["status"]} />}
      bulkActions={
        <BulkActions
          actions={[
            { label: "Approve", verb: "Approved", run: ids => onUpdate(ids, "approved") },
            { label: "Deny", verb: "Denied", run: ids => onUpdate(ids, "denied") },
          ]}
        />
      }
      detail={row => <DetailsSheet label="Request details" title={row.requester} />}
    />
  );
}

Foundations

The values everything else is built from. Use a token, never a raw value; if a value you need is missing, add the token first.

  • Colour16 tokensTen monochrome tokens plus three message colours and the danger button’s red, each with a dark value.
  • Radius, shadow and height11 tokensFour radii plus full, three shadows for things that float, three control heights.
  • Spacing13 stepsA 4px grid, with half steps for the inside of controls.
  • Type8 stepsAn eight-step ramp: six fixed sizes and two that scale with the viewport.

Rules

  • Never use colour alone. Selection is an ink border or bar, sort is weight and an arrow, a chosen card has a filled mark.
  • Message colours appear only in messages and their icons, and always beside words that say the same thing.
  • --focus is for the focus ring and nothing else, so focus is always the one blue on the screen.
  • Dark mode follows the OS; data-theme on <html> overrides it. Windows High Contrast gets system colours.
  • Body text on every background passes 4.5:1; --ink-faint is the lightest text allowed.

Rules

  • Label with a verb and its object: “Delete 3 assets”, “Add module”. Never “OK”.

  • Icon-only buttons need a name: aria-label or visually hidden text.
  • High contrast: every button gets a ButtonText border; pressed gets a Highlight border.

Segmented control

Choose one of a few short options, inside one tray. Use it to filter content by one property, or to switch the view or mode of what’s below, such as grid or list.

Keyboard

Segmented control keyboard support
TabMove into the group, onto the chosen option, and out again. The group is one Tab stop.
← → ↑ ↓Move to the next or previous option and choose it.
SpaceChoose the focused option.
EscClose an option’s tooltip. The arrow keys reach unavailable options but don’t choose them; the next arrow moves on.

Screen reader

  • Built from real radio inputs in a radiogroup, so people hear “Type, Video 4, radio button, checked, 3 of 6”.
  • Icon-only options keep their text label as the radio’s name, and show it in the library tooltip on hover and focus.
  • An unavailable option uses aria-disabled, so people can still reach it and hear why: “Audio 2, radio button, dimmed, 4 of 4. No audio in this library yet.” Its content fades; the focus ring doesn’t.
  • High contrast: the chosen option is filled with Highlight.

Component · CSS + React

Switch

Turns one setting on or off, and the change takes effect straight away. A native checkbox with role="switch", so screen readers hear “Include image, switch, on”.

When it’s unavailable

An unavailable switch stays in the Tab order, can’t be flipped, and says why: in a tooltip when people point at it or tab to it, and as its description for screen readers, “Proctoring, switch, off, dimmed. Turn on recording in Settings first.” It uses aria-disabled rather than the disabled attribute, which would take it out of the Tab order and hide the reason.

  • Always give a reason, and say how to make it available if people can.
  • Show what it’s set to, even when it can’t change: an unavailable switch that’s on still looks on.

What every field has

As candidates will see it.
Enter a number of minutes, such as 45.
  • A visible label above the control, joined to it with for and id. Placeholders are examples, never labels: they vanish as people type.
  • A description under the control, only when it helps, joined with aria-describedby so it’s read with the label.

  • Errors replace the description: an icon and words that say how to fix it, a 2px ink border, and aria-invalid="true". Never colour alone.

When to check

  • Check when people submit, not while they type. Then move focus to an error summary at the top that links to each field, as in the Multi-step form pattern.

  • Never disable the submit button to show the form is incomplete; people can’t find out why.
  • Keep what people typed when something fails. Never clear a field to show it was wrong.

Text area

Several lines of text: instructions, notes, a reason. It grows downward when people drag its corner, and can count characters against a limit.

Character counter

  • Show what’s left (“102 characters left”), and when people go over, say by how much (“6 characters too many”) in semibold ink. Never cut off what they typed.
